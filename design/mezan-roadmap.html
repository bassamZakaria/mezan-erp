Phases 0–9 and 11–12 are on main; typecheck and lint pass. The gaps that remain in v1 are narrower than the phase list suggests, and concentrated in one place:

  • Phase 10 is the outlier — the engines (workflow gate, numbering, audit) exist, but none of the admin UIs do, and there is no notification rules engine at all, only an event bus.
  • 9 screens run the domain in the browser, not through their mounted API routes: stock balance/transfers/adjustments/counts, exchange rates, FX revaluation, cost-center P&L, reconciliation, ETA. Real rules, no persistence.
  • Never built: label printing, product templates/variants, inventory write-down batch, all 8 domain hub pages, branch 360, profile screen, production dashboard, the print-template designer (the page is a live preview instead).
  • Implemented but never wired: the audit trail, the credit-control check, LAN multi-till and four route groups (stock transfers/adjustments, physical counts, balance reconciliation) are engine-complete and test-covered, but createBackend never supplies them to createApp — they 404 or silently no-op in the running app. There is also no i18n layer: the language selector writes to state nothing reads.
  • Deferred by decision (Phases 13–15): HR/Payroll, POS, cloud/SaaS.

How to pick up work

  1. Start on Phase 0's foundation issues. Nothing else is buildable until the monorepo, persistence layer and app shell land — it's the spike every other phase sits on.
  2. Once Phase 0 · Monorepo + package boundaries merges, every issue tagged parallel-ok can be picked up by a second engineer immediately — no need to wait for the rest of that phase.
  3. Otherwise follow the numbered order: it encodes real dependency chains (e.g. Sales Invoices need Chart of Accounts + the posting engine first). ★ priority phases (3–9) are the stakeholder-named priority run — Sales, Purchases, Inventory, Accounting, Treasury, Installments.
