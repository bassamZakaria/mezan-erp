**The single list of known defects.** Every test run reads this before starting
and updates it before finishing. Nothing else tracks defects — if it is not
here, it is not tracked.

Updated 2026-08-27. The defect-clearing pass closed every defect that was open —
D28, D38, D46, D48, D49, D51, D52, D54 (both of them) and D55, as F93–F102 — and
then closed D57 and D58, which that same pass opened by driving the seeded app
in the English UI. The register is empty of open defects.

The same pass repaired the register itself: 23 rows sat in BOTH the Open and the
Fixed table, so this file reported 32 open while its own prose said four; F13–F26
each appeared twice with different content, from two numbering runs colliding
(the second occurrences are now F103–F116); and two unrelated defects shared the
id D54. A defect now appears exactly once.

## How to use this file

**Before a test run**, read the OPEN table. Those defects will show up. Note
that you saw them and move on — re-filing a known defect as a new finding buries
whatever is actually new.

**After a test run**, update this file in the same commit as any fix:

- Found something new → add a row, with the **measured** evidence, not a
  description. "Off by exactly 122.00" is a defect report; "reconciliation looks
  wrong" is a feeling.
- Fixed something → move it to FIXED with the commit that fixed it. **Do not
  delete it** — a fixed defect is how you recognise its regression.
- Proved something was a false alarm → move it to NOT A DEFECT with what
  actually caused the reading. Silently dropping it means the next person
  rediscovers and re-reports it.

A stale register is worse than none: it is how a real regression gets waved
through as "oh, that's the known one".

added the multi-year seed history (F138 below); it had been invisible because no

scenarios` passes 6176 assertions with all four invariants at exactly zero on
the seeded tenant: trial balance, inventory vs GL 1200, AP vs GL 2100, AR vs
GL 1105. The assertion count rose with the seed: the suites iterate over the

This table used to carry 23 rows that the Fixed table ALSO carried — a defect
was moved without being removed, so the register said 32 open while its own
prose said four. Those rows are gone; a defect now appears exactly once.

And a closed register is not the same as a clean product: it means the ones
found and written down are closed. The next one gets found the way these were —
by driving a seeded app and comparing two numbers that must agree. Two things
are open by DECISION rather than by patch, and stay listed so nobody re-files
them:

- outbound notification channels do not deliver. `notifications/engine.ts` stamps
  every channel but `in_app` as `"queued"` and nothing drains the queue.
  **Corrected 2026-08-27:** the channel type is `"in_app" | "email" | "push"` —
  there is **no WhatsApp channel**, so the earlier wording here was wrong. An SMTP
  transport now exists (`packages/api/src/smtp-client.ts`, used by the settings
  test-send), so email is a delivery/retry decision for a product that is normally
  offline, not a missing transport.

- the API-key and webhook **backend** — `packages/domain/src/api-keys`,
  `packages/domain/src/webhooks`, their contracts and their routes — has no
  consumer. The two screens that drove it were deleted (F129) because a
  desktop, offline-first v1 has nothing to call them; API keys are not used for
  request auth either. Removing the rest reaches into the webhook dispatcher
  that document events run through, which is a wider change than deleting a
  screen, so it is filed rather than done.

The workflow `minAmount` item that used to sit here is gone: the field no longer
exists anywhere in the repo (DEC-1, closed 2026-08-27).

D1's last residue is closed too: the invoice screen's collect action creates and
confirms a REAL collection voucher and allocates it, which is what the reference
product does (its "Collect" requires a treasury account and applies against
invoices). There is no longer any path that records a payment the ledger never
hears about.
