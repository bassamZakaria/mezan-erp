# SaaS Slice D — AWS Infrastructure in Terraform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `terraform apply` in `infra/terraform` stands up the whole minimal-cost AWS footprint for the cloud edition: static web on S3 + CloudFront, one Fargate task with an EFS-backed data directory and a backup sidecar, API Gateway in front, Route 53 and ACM for the domain and every tenant subdomain.

**Architecture:** Spec `docs/superpowers/specs/2026-09-14-saas-completion-design.md` §4 is the authority; do not add resources it does not name. Two roots: `infra/terraform/bootstrap` (state bucket + lock table, applied once with local state) and `infra/terraform` (everything else, S3 backend). Provider pins: `hashicorp/aws` `~> 6.64`, `hashicorp/random` `~> 3.9`, Terraform `>= 1.9`. Region `eu-central-1`; the ACM certificate for CloudFront uses a second provider alias in `us-east-1`.

**Conventions**
- Commit subject only; NEVER `Co-Authored-By` or any trailer; commit by pathspec.
- `terraform fmt -check` and `terraform validate` must pass (run `terraform init -backend=false` in each root first; no AWS credentials are needed for validate). No `terraform plan`/`apply` in this task.
- Every variable has a description and, where sensible, a validation block. Secrets never in tfvars: `platform_owner_password` is `sensitive = true` and defaults to null so `-var` or `TF_VAR_` supplies it.
- Tags: `Project = "mezan"`, `Environment = var.environment` via `default_tags`.
- Names: `mezan-${var.environment}-<resource>`.

| File | Contents |
|---|---|
| `bootstrap/main.tf`, `bootstrap/variables.tf`, `bootstrap/outputs.tf` | `aws_s3_bucket` (versioning, SSE, public access block) + `aws_dynamodb_table` (PAY_PER_REQUEST, `LockID`) |
| `providers.tf` | terraform block with `required_version`, `required_providers`, `backend "s3"` (bucket/key/region/dynamodb_table given at init via `-backend-config`), two aws providers (`eu-central-1`, alias `us_east_1`) with `default_tags` |
| `variables.tf` | `environment`, `domain`, `image_tag`, `app_cpu` (256), `app_memory` (512), `desired_count` (1), `tenant_domain` (defaults to `var.domain`), `platform_owner_email`, `platform_owner_password` (sensitive), `backup_interval_minutes` (15), `log_retention_days` (14), `alarm_email` (optional) |
| `network.tf` | VPC 10.42.0.0/16, two public subnets across two AZs (`data "aws_availability_zones"`), IGW, route table, security groups `app` (ingress 8080 from `vpc_link` SG; egress all), `vpc_link` (egress 8080 to `app`), `efs` (ingress 2049 from `app`) |
| `storage.tf` | EFS (`encrypted`, `generalPurpose`, `bursting`, lifecycle `AFTER_30_DAYS` to IA), mount targets in both subnets, access point `/data` uid/gid 1000 with `creation_info`; backup S3 bucket (versioning, SSE, public access block, lifecycle: noncurrent versions expire 30 days, abort incomplete multipart 7 days) |
| `registry.tf` | ECR repo `mezan-${env}-app`, scan on push, lifecycle policy keep last 10 |
| `compute.tf` | CloudWatch log group; IAM execution role (AmazonECSTaskExecutionRolePolicy + SSM `GetParameters` on `/mezan/${env}/*`); task role (S3 put/list on the backup bucket, `elasticfilesystem:ClientMount/ClientWrite` on the access point); ECS cluster (container insights off); task definition FARGATE, `ARM64`, `LINUX`, cpu/memory from vars, volume `data` (EFS, transit encryption, access point, IAM auth), containers `app` (image `${repo}:${var.image_tag}`, port 8080, `mountPoints /data`, env `MEZAN_PLATFORM_DIR=/data`, `MEZAN_SQLITE_EXCLUSIVE=1`, `MEZAN_TENANT_DOMAIN`, `MEZAN_TRUST_PROXY=1`, `NODE_ENV=production`, `PORT=8080`, secrets `MEZAN_PLATFORM_OWNER_EMAIL` and `MEZAN_PLATFORM_OWNER_PASSWORD` from SSM ARNs, awslogs, healthCheck `wget -qO- http://127.0.0.1:8080/healthz`) and `backup` (image `public.ecr.aws/aws-cli/aws-cli:latest`, same volume read-only at `/data`, `entryPoint ["/bin/sh","-c"]`, command a loop: `while true; do aws s3 sync /data/backups s3://${bucket}/backups --only-show-errors; sleep ${interval}; done`, `essential = false`, awslogs); ECS service: launch type FARGATE, `desired_count`, network config both subnets + `app` SG + `assign_public_ip = true`, `deployment_minimum_healthy_percent = 0`, `deployment_maximum_percent = 100`, `deployment_circuit_breaker { enable = true, rollback = true }`, `service_registries` to the Cloud Map service; Cloud Map private DNS namespace `mezan-${env}.local` in the VPC and service `app` (A record, TTL 10, `health_check_custom_config`) |
| `api.tf` | `aws_apigatewayv2_api` HTTP, `aws_apigatewayv2_vpc_link` (both subnets, `vpc_link` SG), integration `HTTP_PROXY` to the Cloud Map service ARN with `connection_type = "VPC_LINK"`, method ANY, route `$default`, stage `$default` auto-deploy with throttling burst 100 rate 50, access logs to a log group |
| `cdn.tf` | S3 web bucket (private, SSE, public access block, policy allowing the distribution's OAC via `AWS:SourceArn`), `aws_cloudfront_origin_access_control`, `aws_cloudfront_function` (viewer-request, JS: `request.headers['x-forwarded-host'] = { value: request.headers.host.value }; return request;`), ACM cert in `us_east_1` for `var.domain` and `*.${var.domain}` with DNS validation + `aws_acm_certificate_validation`, distribution: aliases both, `default_root_object = "index.html"`, origin S3 with OAC, origin API (`replace(aws_apigatewayv2_api.main.api_endpoint, "https://", "")`, `custom_origin_config` https-only TLSv1.2), default behaviour → S3 (cache policy `Managed-CachingOptimized`, viewer https redirect, compress, function association), ordered behaviour `/api/*` → API (`Managed-CachingDisabled`, origin request policy `Managed-AllViewerExceptHostHeader`, all methods), custom error responses 403 and 404 → `/index.html` 200, viewer certificate the ACM cert `sni-only` TLSv1.2_2021, `price_class = "PriceClass_100"`, IPv6 on |
